# Application-owned minute summaries

RecordPrep owns one fixed, practice-neutral minute method for **all new generation**,
including custom/historical profiles and unassigned compatibility contexts. The canonical
editorial instructions and fictional examples are in
`.pi/skills/recordprep-summarize-minutes/SKILL.md`. Profiles own only Report Names,
Form Names, hearing digest topics and report digest topics; those methods are unchanged.

## What users see

Profile settings → Summaries contains **Hearing digest topics** and **Report digest
topics** only. Either page's **About summaries → View full prompts…** inspector keeps
**Minute-order summary** in its existing task selector. That task displays the fixed
system, canonical skill/examples, launch, audited tools and runtime placeholders.
It has no template/current-draft switch or unsaved-draft notice; invalid unrelated
drafts do not affect it. Search, Copy, Close/Escape and the hearing/report draft modes
remain. There is no minute editor, reset control, extra menu item or reference window.

The compact presentation is unchanged:

```text
Date — Hearing type
Appearances: …
Orders: …
Next: …
```

Lines remain adjacent, with one blank line between entries and no bullets. Existing
Focus and PDF label emphasis/spacing stay unchanged. Select normally one or two
headline outcomes in plain English, with essential distinctions, conditions and
substantive deadlines; this is not a hard outcome/word limit or text filter. There
is no extra model pass, blocking editorial validator or repair loop. Attendance uses
explicit evidence from any page, including recorded remote attendance. Counsel alone
and omitted names establish neither presence nor absence. Roles come from this order,
not a practice assumption, role catalog or participant index. Unknown evidence remains
advisory/unclear without cancelling useful output. Next is only the next substantive
hearing type/date, never report calendars or scheduling mechanics.

## Instruction and freshness contract

`minute_summaries.application_guidance()` and `application_contract(project_dir)` are
pure shared runtime/inspection builders. `stage_config` reads shared effective Pi
model/reasoning, never minute configuration or profile resources. There is no exact-default
substitution or additional/practice guidance section. The launch uses the established
literal-space `/skill:` delivery. Every new run explicitly loads the retained filename
`recordprep-profile-minute-tools.ts`, with exactly source-read and candidate-submit.
The parental `recordprep-minute-tools.ts` remains historical, never selected by new runs.
Complete source-before-submit, capacity preflight, Stop/stall handling, locks and Python-only
publication remain safety boundaries.

Minute content contract **9** retains presentation `recordprep-minute-compact-labels-2`.
New checkpoint/final envelopes are **schema 5**, with `application_contract` containing
`method_id`, `contract_version`, and `component_sha256`, not required profile provenance.
The component hashes effective fixed guidance, canonical skill, active tool contract,
system, literal-space launch/delivery identity, presentation and attendance contracts.
Per-order fingerprints retain original source pages, ranges, labels/citations and effective
model/reasoning. Profile identity, historical minute/config prose and unrelated naming/topic
edits do not stale identical current minute work. Full current-selection guards still
prevent unsafe concurrent publication. Source-map preparation provenance records the fixed
minute component in its existing descriptive format; it cannot supply instructions.

Rows retain the schema-4 shape, including compatibility `positions`, source-described
`role_label`, attendance evidence and `next_hearing`; new tools request no positions
narrative. Historical checkpoint schemas **1–4** read exactly as stored, without altered
attendance semantics, fabricated freshness or prose reformatting. They are never reused
as contract-9 work solely because their text looks similar. New unchanged work reuses
checkpoints with zero model calls. Successful orders remain resumable after a later
failure; invalid source/candidate, Stop, changed inputs or unsafe publication preserves
the prior final. Zero orders need no model. Completion badges and Resume remain based on
output presence, not freshness; read-only checks never write/delete/regenerate outputs.

`profile_api` stays **1**. Content schema **10** omits `minutes` and rejects its
reintroduction. Every supported schema's compiled minute resource list is empty.
Schemas **1–9** remain readable and byte-preserved. Only explicit Create/Save/Reset
publishes a new schema-10 revision; opening/cancelling settings writes nothing. Legacy
initialization never imports minute prose. Existing configuration keys/values are inert
and preserved on ordinary saves; absent keys stay absent.

Bundled Dependency is **1.11.0**; its active `minutes.md` is removed. Naming, topic,
policy and caption bytes are unchanged from 1.10.0. Its prior shipped digest
`975fc7ddea124a0aa43cb83b77aef2cf0128f0af4e6c858fdf002dcbd80ee6c8` remains a known
baseline, not personal ownership. Historical public fixtures and the retired General

The only Focus companion is byte-identical `profile_contract.py`, compatibility tests
and documentation. `profile_artifacts.py`, research instructions, UI, minute TXT/edition
formats, source maps and runtime cross-import boundaries are unchanged.

## Adoption

Updating RecordPrep applies this method to the **next explicit minute generation**.
No profile reset/save is required, including custom profiles. Existing summaries remain
readable and unchanged; updating does not generate anything or restart the app.

To adopt for an existing bundle, explicitly run **Create minute-order summaries**.
Affected orders need new model work: this is not a free reformat. No classification,
boundary, participant, hearing-summary or report-summary rerun is required solely for this
change. Refresh dependent editions, overview and source map through their normal flows
when desired. Offline validation establishes ownership/delivery/safety/rendering, not
live-model factual accuracy or editorial quality; no paid evaluation is implied.

Exact isolated results and limitations: [validation](application-minutes-validation.md).
Older minute documents describe historical profile ownership/unassigned generation;
this document supersedes those statements, not their compatible presentation details.
