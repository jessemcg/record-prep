# Shipped practice profiles and personal settings

RecordPrep ships **California Juvenile Dependency**, the initial application selection
and default starting profile for **Create profiles**. Any available saved profile
can be used as a base, including future specialties such as California Criminal Law. Profiles are independent of bundles;
see [application profiles and portable storage](application-profiles.md) for the
current selection, Save, resume and synchronization contract. Dependency is a complete public specialty, useful
without anyone's private configuration. Focus now uses one fixed specialty-neutral
research method, not profiles; no Focus counterpart is needed to consume a bundle.
There is no profile repository, download, sibling package import or automatic
cross-app synchronization. Portable profile settings may be explicitly selected
outside bundles; historical case pins no longer authorize instructions.

## Structured settings (current)

Dependency **1.8.0**, content schema **8**, provides five flat Classification
destinations: **Reporter transcript page types**, **Clerk transcript page types**,
**First pages**, **Report Names**, and **Form Names**. Edit descriptions,
not fixed page-type/output keys. RT/CT uses best fit across all descriptions, not
list order. First pages has four cards: hearing, minute order, form and report.
Hearing/minute dates are fixed application instructions, inspectable but not editable.
Approved report/form names are retained stable-ID cards with optional recognition
descriptions and organizational Add/Remove/reorder actions, not Markdown bullet syntax.
These catalogs supply naming only, not structural page recognition or start checks.
Advanced checks every report page independently, including adjacent and unnamed
reports. Names uses marked first pages, and unnamed starts still break earlier
report ranges. CT catalog previews/links and report-gap filling are removed.
See [report starts, cost and compatibility](report-first-pages.md).
There is no Detention-specific date exception; report dates use the general method.

Both About disclosures offer **View full prompts…**, with a placeholder template
(default) or a frozen unsaved draft, search and Copy. No case, credentials, Node or
model request is needed. The separately authorized [summary skill-delivery fix](summary-skill-delivery.md)
now verifies expansion of all five summary skills through the installed Pi SDK.
The inspector distinguishes staged skills from launch messages before expansion;
missing or stale audits remain visible. Invalid compatibility JSON is frozen as literal raw text with an incomplete/invalid-draft warning; the inspector never labels the last valid naming object as the current draft. Valid unrelated tasks remain inspectable, with the limitation visible.
See the [ownership/dependency inventory and validation](profile-ownership-audit.md) and the [current schema, information review,
compatibility and delivery verification](structured-classification.md) and
[validation](structured-classification-validation.md). Historical format details
below apply to older immutable snapshots where identified; no private migration or
automatic output regeneration occurs.

## Choose, edit, save

The chosen profile name appears as a subtitle immediately below the app title,
not as a separate banner. The hamburger menu shows the profile dropdown and
**Profile settings** as compact, normal-weight, left-aligned menu items. Names
wrap in full and a check marks the current choice. Selecting a dropdown item
immediately applies that profile; there is no separate **Use profile** action or
chooser dialog. **Profile settings** edits the selected RecordPrep profile. Opening
the dropdown alone changes nothing; activating an item changes the application-wide
selection, never the bundle. A failed storage transaction retains the current choice.

Profile settings opens in an independent, non-modal window with minimize, maximize
and close controls. It can be moved/resized independently while the main app stays
usable. Active work or changing cases still blocks stale settings application.
The window opens on boxed expandable Classification and Summaries destinations.
Choosing a page opens its retained editor with Back/Save controls and a prompt-page
chooser, not a permanent sidebar. The header uses Model settings' flat toolbar
styling and shares the window background.
RecordPrep has no General section or second profile picker/default checkbox;
it edits the already-selected profile. Focus has no profile controls; its ordinary
model/appearance/speech/launch controls are in Settings.
**Create profiles** is a hamburger-menu link immediately below **Profile settings**,
not a button at the bottom of the sidebar. Its Cancel/Create actions use flat
buttons without an extra selectable hover background. Saving the selected profile
advances its application-wide revision for future preparation.
The profile name remains beneath the window title; **Save** stays in each retained destination's header. **Close** offers **Keep Editing** / **Discard Unsaved Changes** when dirty, never Save-and-close. Only successful Save advances the baseline, without closing or changing destination. Switching pages preserves unsaved edits and each page's scroll position.
At narrow widths, Back returns to the full-width destination list; retained inline
cards and wrapped editors use the available width without a sidebar. A built-in opens with
complete populated settings; personal settings appear in place of its baseline.
Create profiles has a **Create a profile** section asking for a name and starting
profile (California Juvenile Dependency by default). Identifiers are generated internally. Create opens
an unsaved draft; only Save keeps it. Cancelling a draft saves nothing.

Its **Delete a personal profile** section lists only user-created specialties,
not built-ins (including personal edits of built-ins). Choose one and press
**Delete profile…**, then confirm. Delete removes the chooser entry, never its accepted revision files or existing
case metadata. Existing case output remains readable. Deleting the selected profile
returns the application selection to California Juvenile Dependency. No case is rebound and nothing is
regenerated. Reusing the name creates a new identity; old open drafts
cannot resurrect a deleted identity. Stale profile/default/case state or active
work blocks deletion without repairing private files.

Profile settings opens at its expandable destination home. Its only main categories are **Classification**
and **Summaries**. Case Overview remains a pipeline step, not a settings category.
One fixed, practice-neutral method reads all summaries completely and supplies Focus
with central parties, record-bounded procedural posture, chronological material events,
neutral principal disputes and record scope/gaps. It preserves allegations versus
findings, uncertainty and identity-only participant metadata; it has no word/event
quotas, assumed appeal or outside legal analysis. Historical overview instructions
are ignored, not rewritten. The five-section format and nonauthoritative disclaimer
remain unchanged. Every Classification page has a collapsed **About classification** disclosure in the ordinary page scroller. It expands to its full natural height, pushing editors below it, and explains classification and date/name extraction. It ends with the display-only progression **Page types → First pages → Dates & names → Table of contents → Boundaries**; this is not navigation or live progress. There is no pinned explainer or separate capped explanation scroller.
RT and CT page types come first, followed by First pages, Report Names,
and Form Names, without child indentation or date editors. Subtitles identify
pipeline stages, not matching precedence. Retained expandable recognition cards
show friendly names, a small read-only output key and full-width wrapped text.

Each classification task combines its fixed method with relevant recognition data.
There is no Common guidance editor or hidden shared instruction block in newly saved
profiles. Report Names/Form Names supply naming-only data. Put page-specific
specialty rules in the relevant structural page-type card. Advanced selects hearing,
minute-order, form and report start checks from Basic’s types; Dates uses marked
hearing/minute-order first pages. Names reads report name/date and form names only
from marked first pages. Both named and unnamed report starts terminate preceding
report ranges; no name match is required to detect a document break. Hearing TOC labels come from hearing dates—not
a separate hearing-name prompt. Correction stages retain their existing positions;
TOC and document boundaries use these classification results.

Structural page types and response keys are application-owned, shared across legal
fields. Profiles customize recognition clues, not category names. Each Basic editor
shows the supported RT or CT labels from the same definition used by the runtime
validator. Advanced returns `first_page: yes/no`; Python adds `RT_body_first_page`,
`CT_minute_order_first_page`, `CT_form_first_page` or `CT_report_first_page`. Dates returns `date` or an empty
string. Naming uses separate approved names, not new page types. Certificates,
motions, notices and proofs of service remain recognized structural categories.

The editor warns as you type when an RT_/CT_/CR_ label reference is unsupported for
the current task. This is advisory token checking, not semantic proof: comparisons
and negations can intentionally mention other labels, and prose-only contradictions
may go undetected. Warnings do not block Save, rewrite guidance, reject historical
profiles or loosen runtime validation. Review a warning before running a case.

Create a profile by copying California Juvenile Dependency or any other available
profile, then tailoring its instructions, digest topics and approved report/form
names. The copy retains the base's actual language and formatting; it is not
neutralized automatically. Review and replace Dependency-specific guidance when
creating a different specialty. California Criminal Law is not yet bundled.

**General Court Record is retired.** It is absent from selection and starting-profile
lists, including previously accepted or edited copies of that built-in identity.
An old General application selection resolves to the current personal or bundled
Dependency profile without rewriting any settings. Independently created custom
profiles remain available, even if originally copied from General. Saved General
revisions and case data remain byte-preserved and readable; an internal compatibility
archive supports historical minute defaults and schema-1 readers/editing only.
No private profile is migrated or deleted, and no prepared output is regenerated.

Summaries has a naturally expanding **About summaries** disclosure on each of exactly three pages: **Hearing digest topics**, **Report digest topics**, and **Minute orders**. There is no pinned breadcrumb or internal title; the explanation ends with the linear overview **Each hearing /
report → Topic digest + quotes → Narrative section → Hearing / report summary**.
Stage 1 reads each complete hearing or report across all its pages; after the digests
are ready, Stage 2 synthesizes hearing by hearing or report by report, producing
separate final hearing and report summaries. Relevant information may be sparse or
dense; substance determines detail, without word targets or quotas. A long hearing
section still needs short, focused individual paragraphs, regrouped when issues,
arguments, attribution or rulings change rather than copied as category-sized blocks.
Hearing extraction distributes meaningful quote anchors across retained positions,
conditions, disputed evidence and reasons. Synthesis distributes appropriate anchors
through substantive paragraphs; brief connective prose or points without suitable
anchors may remain paraphrase, never fabricated or misapplied quotations. One submitted
array entry represents one paragraph; explicit blank-line breaks also survive rendering.
These are model instructions, not blocking quality gates or automatic repair passes.
The [hearing editorial follow-up](hearing-editorial.md) makes the substantive purpose
or consequential result the opening, reduces overview/party-argument repetition,
improves quotation grammar and attribution, and preserves unresolved conflicting
accounts explicitly. Routine recitals get less weight; consequential conditions,
findings, burdens, review rights and dates remain. Newly rendered hearing summaries
omit the capitalization announcement; quotation normalization is unchanged. This is
synthesis-only: valid hearing digests remain reusable and report/minute methods are
unchanged by that hearing follow-up. The separate [report editorial follow-up](report-editorial.md)
now stages the visible `recordprep-synthesize-reports/SKILL.md` unchanged for both
profile-bound and unassigned reports, rather than replacing it with the generic
profile template. It leads with the main attributed conclusion/development and
necessary qualification, reduces category-shaped repetition, improves quotation
grammar/attribution and preserves counterevidence. Report renderer8 also omits the
announcement without changing capitalization safeguards. Only report synthesis is
affected; topics and still-current digests remain unchanged/reusable.
See [earlier implementation and bounded comparison](hearing-selection-validation.md)
for historical model-test results; that comparison did not test the later editorial
instructions and is not a claim of their model-quality acceptance.
**Digest topics** are the hearing/report customization surface. Fixed application
instructions preserve the pre-profile materiality, adaptive-detail, quotation and
cohesive-narrative method. No additional digest or narrative instruction fields
exist in new profiles or the UI; old snapshot fields are never compiled or imported
from legacy settings. Minute orders retain their separate single-stage,
complete-order summary flow, described on their page. There is no attendance-policy
selector. All cases load the same visible, specialty-neutral
`recordprep-summarize-minutes/SKILL.md`; there is no profile-specific replacement
skill. Its shared method normally selects **one or two headline outcomes**, not all
material detail or an inventory of findings, services and directions. Keep the
qualifications needed to state those outcomes accurately; another outcome only when
omission would mislead about disposition. Python renders **Date — Hearing type**,
then **Appearances / Orders / Next** labeled lines without dashes/bullets. Focus styles
the plain-text labels in bold, without quote-link or Markdown markers. Orders states
the result in simple, plain English, retaining essential legal distinctions/conditions.
Exclude routine report receipt/preparation, filing/portal deadlines, clerical/calendar
mechanics and conditional late-filing sanctions warnings. Administrative-only orders
say **No substantive orders recorded.**, not filler or an invented outcome. Actually
imposed consequential sanctions and substantive relief deadlines remain eligible.
There is no separate party-position
submission; an essential objection belongs with its ruling. Next gives only the next
substantive hearing type/date, excluding report-only hearings and future report filing/due
dates even if earlier. Do not move that report calendar into Orders. Submission fields are
containers, not demands for a narrative in each.
Profiles provide specialty terminology, relevant participants and emphasis: for
California Dependency, that includes the parents and dependency orders rather than
forcing those concepts on other specialties. Specialty guidance remains subordinate to the
shared selection and safety method. No fixed length cap or mechanical truncation.
Current contract8 and label-v2 identity are documented in [plain-English minute
entries](minute-plain.md). See [earlier compact entries and validation](minute-compact.md); the
[first selection attempt](minute-selection.md) is historical, not quality acceptance.
All pages may supply attendance evidence;
counsel alone establishes neither presence nor absence. Unclear attendance and
missing/unclear future settings remain explicit; no reporting-status sentence is
added. Exact former bundled minute prompts resolve to the new default without
rewriting private snapshots; genuinely custom minute prose remains unchanged. The shared explainer ends
with the distinction between topic-organized digests and narrative sections.
Restored contracts mark profile-bound digests and narratives regeneration-pending;
existing output stays untouched until an explicit summary run.
There is no Participants / Witnesses settings area. One fixed general identification
contract applies to every hearing, regardless of specialty. It records source-supported
names, roles/relationships, attorney representation, personal/remote attendance,
express absences, speaking, sworn testimony and examinations, with citations and
uncertainty. Role labels describe the source rather than an editable category catalog.
The index still supports hearing summaries, case overview and Focus navigation.
Minute orders use only the current order, not this index or a profile role catalog. Report naming and form naming
use stable-ID approved-name cards. Each has an editable canonical name and optional
description/matching instructions, including any required form heading/code. The
same structured names supply the model prompt and Python's exact membership check.
For current v4 cards no naming-mode selector, technical rule editor, or special Markdown syntax is needed. Historical v1/v2 resources instead expose their complete JSON, v3 its literal prose; there is no guessed splitting or automatic conversion.
Dependency retains its reviewed names and form codes; copies inherit them until
you edit them for the new specialty. **Only successfully named reports enter
the report TOC and standalone report-summary worklist.** Any profile without approved
report names therefore produces no eligible report summaries. Report dates can still
be extracted independently, but cannot substitute for a name. Named single-page,
missing-date and different same-name/date reports remain eligible. Unnamed runs,
including continuations exposed by classification interruptions, are omitted from
report navigation/summarization, not deleted or merged with neighboring reports.
Every original page and classification remains available for direct-source research.
This approved policy replaces the former provisional-report-label policy. Forms
with no accepted name are omitted from the Forms TOC, without deleting their source
pages or structural classifications. An empty form name is not replaced by an
“Untitled form” entry. Existing output stays unchanged until explicit application
runs: **Build TOC → Correct TOC → Find boundaries → Correct boundaries**.
Correct TOC retains the first entry per recognized minute-order date in source order;
unknown dates remain separate. This applies to profiles too, but does not deduplicate
their underlying same-day order boundaries, summaries or checkpoints. Old output is
still displayed as stored. Derived-selection freshness v4 requires the explicit
organizing refresh, not reclassification or renaming. Unchanged hearing/RT inputs
reuse participants afterward; organizing-only changes do not stale minute checkpoints.
The separately changed minute selection method does require explicit paid regeneration;
old output remains readable and untouched until then. Report worklist pruning reuses unchanged named-report digests with contiguous ordinals,
but report synthesis reruns without removed fragments' context.
Summary topics are expandable cards with editable names/instructions and add,
remove and reorder actions. Renaming a topic does not change its stable ID.
Topic instruction editors unwrap hard-wrapped prose to use the available width,
while preserving paragraph breaks and structured blocks such as lists. This is
initial display formatting only: opening or browsing does not change saved guidance
or mark the profile dirty. Editing a topic makes its displayed text the draft;
only the normal Save flow persists that draft.
Topics guide capture from each complete hearing or report, not required headings
in the narrative. New structured RecordPrep profiles use content schema 8, without Common guidance, the four
extra summary instruction resources, role catalogs, participant or overview instructions. Explicit editing upgrades only a draft; historical
accepted revisions are never rewritten. Focus's neutral research method has no
editable guidance or search priorities; document labels supply navigation, not
automatic evidence authority.

Close offers **Keep Editing / Discard Unsaved Changes**, never Save-and-close.
Opening, inspecting and cancelling do not write a registry, snapshot, settings
file or case.

### Reset to bundled prompts

On the Profile settings home, **Bundled prompts → Reset to bundled…** is shown
only for the edited profile's exact shipped application/specialty identity, not
its name or creation base. Independent custom copies and retired General have no
reset target. Future shipped specialties use the same action.

Cancel (also the default/close response) changes nothing. **Reset and Save**
replaces all Classification and Summaries guidance, approved names, topic catalogs
and unsaved edits with the installed bundle, and **saves immediately**. This is an
explicit exception to draft-until-Save behavior; no second Save is needed. Model
settings, cases and generated output do not change, and no model runs.

The reset publishes the exact current bundled manifest/resources, including inert
resources and current schema metadata. It keeps personal ownership, advances an
already selected revision without choosing another profile, and retains all prior
immutable revisions. Repeated identical reset is idempotent. It is a one-time
synchronization, not automatic tracking of future releases.

Production preview/compilers and the existing head/default, work/case/storage and
locked publication guards still apply, even to an invalid discarded draft. A bundle
changed during confirmation requires another confirmation. Failure keeps the live
draft/selection; stale settings require reopening, never refreshed expectations to
force publication. A post-publication display failure says **saved, refresh required**.
Surviving topic IDs/cards/buffers, navigation and expanded states are retained.
Undo changes the new unsaved draft, not the saved revision. See
[reset validation](bundled-reset-validation.md). Save needs no file picker, export, registration, technical version
entry, separate acceptance step or Git operation.

Saving the selected profile advances application guidance immediately, without a
separate case-use confirmation. Every dropdown choice is remembered for subsequent
runs and launches, whether a case is open or not. Existing summaries and other
outputs are never regenerated by selection or Save. Create files writes no profile
pin; old pins are preserved as inert historical data. Instruction fingerprints in
prepared artifacts protect explicit-run checkpoint reuse from incompatible guidance changes; output-presence badges and Resume do not force regeneration for changed settings.

RecordPrep's header has dim **Choose case bundle**, **Choose PDF(s)** and
**Clear current case** buttons, in that order. The trash button clears only the
current selection and displayed progress/activity; no PDF, bundle, case name or
generated artifact is deleted. It also drops pending layout/profile choices and
invalidates old file dialogs and case-bound profile drafts. Stop active work and
close the TOC editor before clearing; ordinary Model settings and Profile settings
remain usable without a case. Clearing drops the in-memory proposal but does not
forget the remembered new-case default or saved personal profile content.

Synchronized RecordPrep case metadata accepts ordinary owner-owned `0755`/`0775`
directories and `0644`/`0664` files, without chmod/repair. Symlinks, hardlinked or
nonregular files, foreign ownership, executable metadata files and world-writable
metadata remain rejected. Compare-and-swap and publication locking still protect
application-selection changes. Private XDG profile stores remain owner-only;
explicit portable stores use separate sync-compatible mode checks. Missing
historical pinned revisions have no effect on current generation or selection.

Focus automatically uses its fixed neutral method for every explicit new question,
including previously profile-bound cases. No confirmation, advanced profile choice,
private-store lookup or RecordPrep regeneration is required. RecordPrep selection
alone makes no model request, renames no case and regenerates nothing.

## Storage and releases

| Data | Location | Version controlled? |
| --- | --- | --- |
| Complete public specialties | `<package>/resources/practice_profiles/` | Yes |
| Evidence/citation/tool/output/publication safeguards | Application source/resources | Yes |
| Credentials, models, endpoints, workers, commands, recent cases | Existing private application settings | No |
| Personal profiles and edited built-ins | Private immutable snapshots | No |
| Current personal references, initialization and defaults | Private registry | No |
| Generation provenance | Descriptive fingerprints in prepared artifacts; no instruction dependency | No |
| Portable profile settings (optional) | Explicit external folder, registry + snapshots | No |
| Portable folder choice and locks | Machine-local XDG state | No |

Each catalog is explicit: `practice_profiles.BUNDLED_PROFILES`. The current
catalog has one visible entry per identity, not a list of stored revisions.
An edited built-in keeps its visible name. Ordinary acceptance of bundled bytes
is not personal ownership. Exact known shipped content distinguishes historical
ordinary acceptance from real personal edits; optional registry metadata records
ownership and completed initialization only on explicit persistence.

Private roots are `$XDG_CONFIG_HOME/<application>/practice-profiles/registry.json`
and `$XDG_DATA_HOME/<application>/practice-profiles/snapshots/<digest>/` (normal
HOME defaults when unset). Files are private, content-verified and immutable to
the application. Unsafe paths, corrupt registries, unavailable snapshots and
explicitly configured missing defaults are errors, never reasons to reset or
silently substitute another profile. Neither browsing old output nor new work
needs the old output's instruction snapshot. New work needs the current selected
guidance. **Profile storage…** can explicitly save/select a portable folder;
see [storage safeguards](application-profiles.md#portable-profile-settings).

Save validates the complete draft with production compilers, checks the active
work guard, compares expected head/default state, publishes the snapshot, and
atomically updates references/ownership/initialization/default under the registry
lock. Repeated unchanged Save is idempotent. A failed publication may leave an
unauthorized orphan snapshot, never a selected profile. Concurrent changes keep
the draft and require reopening saved settings. Saving the default advances it;
clearing its preference returns to personal Dependency, or bundled Dependency.

A release can add a specialty without registration. Updated bundled guidance
does not overwrite personal edits, rebind case pins, rename cases or regenerate
outputs. Repository/Git changes do not regenerate prepared work.
Execution uses validated frozen current application guidance.

## Previous Dependency settings

The read-only resolver begins with complete shipped Dependency settings and
prepares an allowlisted in-memory personal candidate when previous customization
is applicable. The dropdown and editor share this resolution, so selecting a profile
does not bypass it. Opening does not migrate anything. First explicit Save or
dropdown selection persists privately and records initialization. An existing personal
profile wins and is never repeatedly overlaid.

Empty overrides inherit public guidance. Genuine prose is retained without
unnecessary stripping. Historical built-ins are recognized so retired output
instructions are not reattached as personal guidance. RecordPrep preserves
active classification by task, report/form guidance, hearing/report topics and minute guidance. Retired date/caption, extra-summary and attendance inputs are not imported into fresh candidates; already accepted historical resource bytes remain readable and unchanged. Ambiguous naming prose is retained with a
focused review notice: prose does not invent approved-title/catalog rules.
Focus does not load historical profile/legacy prompt guidance into new research;
old private stores and saved answers remain untouched. No credentials, endpoints, paths, commands or
unrelated configuration fields are copied. Never promote this private candidate
into bundled files, fixtures, logs or commits.

Legacy prompt values remain available to compatibility loaders. The general
settings menu and window are called **Model settings** in RecordPrep, distinct from
**Profile settings**; Focus calls its ordinary controls **Settings**. Their existing model, credential, appearance
and machine controls remain; the rename does not change storage or action names.
Model settings no longer edits practice prompts or the retired direct-API sandbox controls. It
retains production classification API settings and agentic Pi models. RecordPrep's
Infer case uses the shared native-Pi model; its old direct-API page is removed.
End-user prompt testing, its action/window and request/payload paths are removed.
Historical recognition text remains deliberately intact for compatibility.

## Maintainer workflow for public specialties

1. Add a complete readable Markdown/JSON directory under each supporting app's
   own `resources/practice_profiles/` tree.
2. Add its directory name to that app's `BUNDLED_PROFILES` catalog.
3. Validate content, production compilers, component freshness and packaging.
4. Review and commit it as public application guidance; include it in a release.

Focus needs no matching counterpart; preparation specialty identities are descriptive.
Never automatically promote a user's Save, private legacy prose or case material.
No chooser change or specialty-specific pipeline branch is needed within the
supported capability/policy contract. New capabilities still require code.
Low-level export/identity/validation helpers remain for maintenance and tests,
not lawyer-facing management controls.

## Contract and compatibility

The strict stdlib compatibility contract is vendored independently. Keep only
`profile_contract.py` and `profile_artifacts.py` byte-identical with Focus.
RecordPrep owns store/workflow/editor/manager modules independently; six-module,
UI and document parity no longer applies. Artifact/reference compatibility tests
remain; do not introduce sibling runtime imports.

`profile_api` remains 1. Historical Focus content schema 1 remains reader-compatible,
not active guidance. RecordPrep content
schema 2 adds `classification_tasks` (strict JSON keys `rt`, `ct`, `first_hearing`,
`first_minute`, `first_form`, `date_hearing`, `date_minute`) and `case_name` text,
retaining every schema-1 resource. Schema 3 keeps those task fields but removes
the four extra summary instruction resources. Schema 4 additionally removes roles
and participant instructions; historical schemas 1–3 remain readable, and all these
retired fields are inert in every stage's prompts and component fingerprints.
Schema 5 additionally removes overview instructions. Overview compilation selects
no profile resources; it follows the application method and runtime summary inputs.
Schema 6 removes Common guidance from stored resources. Explicit editing and Save
omit its field and file; no hidden backup or automatic distribution into task prompts
is created. Existing immutable schemas 1–5 remain readable, but their common text is
never compiled or fingerprinted. Only the current task's guidance is composed with
the application-owned taxonomy. See [task-only classification](task-only-classification.md). Component
fingerprints isolate Basic/Corrected recognition and Advanced/Corrected starts; Dates is fixed and independent of retired date prose. Schema 1 has neutral application-owned descriptions for every structural label and missing first-page clue, never retired Common or Dependency instructions. Exact legacy active-field matches receive the public adapter even if inactive dates differ; unknown active task prose stays literal. Exact whole-task runtime recognition keeps other tasks independent when one clue changes. A lossless editing draft retains custom inactive date text rather than silently discarding it. Caption
inference uses one application-owned, practice-neutral prompt and its own
source/model/output freshness marker. The native `recordprep-infer-case` skill
reads only private copies of the first three pages and writes only a candidate;
Python validates and publishes it with unchanged-input/selection checks. No
separate caption model or credential settings remain. Stored case-name guidance and legacy
`case_name_prompt` overrides are ignored, not rewritten. There is no case-name
prompt editor; caption inference preserves source names, initials/anonymization
and caption forms without assuming a specialty.
Credentials, first-three-page bounds, filename validation and guarded publication
remain application-owned. Selecting a profile never renames the case.

Schema-1 snapshots remain byte-preserved. Explicit caption inference uses the
same built-in prompt and shared native-Pi model for every case. Caption freshness
now requires the schema-2 marker bound to the source/model/contract/output;
existing names remain readable. Output-presence badges and Resume remain unchanged; only explicit inference checks generation freshness.
Opening a case never renames it or migrates its data.
The retired report-scope field is an explicit exception: it remains readable but
no longer controls extraction. Explicit editing upgrades only an in-memory draft.
Old unversioned (v1) and v2 naming catalogs remain readable with their historical runtime behavior and immutable bytes. Unknown v1/v2 resources use a clearly labeled **full-resource JSON compatibility editor**, shared by Report Names and Form Names, exposing authoritative catalogs, source-title/approved-name mode, heading/code rules and global prose. They are not automatically converted to v4 cards or v3 prose. v3 keeps literal prose editors; v4 keeps ordinary naming cards. Exact known public resources may adapt read-only, without replacing arbitrary custom prose. Save or selecting a bundled revision is deliberate; existing case pins are not rewritten.
Prior private naming prose is preserved for review alongside the approved entries;
no model or heuristic invents a new allowlist from arbitrary prose.

Manifests reject unknown/missing fields, unsupported capabilities/versions,
noncanonical/traversing/executable resource paths, duplicate JSON keys, unsafe
links, oversized files and invalid Unicode. Resources are frozen and verified by
content hash. Topics use stable bounded IDs; historical role catalogs retain their
reader validation only. New participant metadata uses source-described role labels,
not specialty IDs. Naming retains historical source/approved-title modes; profile-bound attendance
uses a fixed complete-order source-evidence rule, not a selectable policy. There is no Formal proposals switch or heading-
