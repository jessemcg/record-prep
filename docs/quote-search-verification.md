# Record-wide Focus-compatible quotation verification

## Meaning of Verified

For new hearing, report and motion digests, **Verified means the quotation produces
at least one Focus-style phrase-search hit on a source page somewhere in the record**.
It does not validate the model's reported page, document, speaker or interpretation.

`recordprep/record_quote_search.py` checks the reported page first, then the other
numbered files in the bundle's `text_pages` inventory, stopping at the first hit.
Every page is searched individually. There is no cross-page joining, unique-match
requirement, neighboring-page restriction, new model call or persistent search index.
Repeated matches are acceptable: Focus can navigate between them. A quotation that
exists only across a page boundary remains Unverified, consistent with Focus Find.
Summaries, images, arbitrary filenames and generated prose are not searched.

The extraction model still receives only its authorized document/packet. Existing
checks on usable candidate text and its in-document reported page remain; malformed
or out-of-scope evidence is not rescued. Only the deterministic text verification
has record-wide scope. A match elsewhere is not new evidence supporting the digest.

## Page metadata and Markdown

The saved `file_page` remains the model's reported page; Python does not silently
correct it or record a supposedly unique destination. New visible quote labels say:

`Quote: <id> — Model-reported file page 23 — Verified`

The existing `source_sha256` and optional exact offsets still refer to that reported
page, not a hit found elsewhere. No new page range or quotation metadata schema is
needed. New readers accept both this label and historical `File page` labels while
preserving the recorded rows and verification flags. Reading an old digest never
rewrites it. An old Verified result was a narrower page match and remains readable.

## Matching parity with Focus

`quote_search.py` mirrors Focus core phrase preparation, NFKC/typographic
normalization, case-insensitive regex matching, word-boundary quote tolerance,
intraword spacing, bounded line breaks and intervening numeric tokens. ASCII `|`
becomes a space in both query and search copy. Thus `NEW 3 | INFORMATION` matches
`NEW INFORMATION` without modifying the source. Numeric bridging is a search rule,
not proof that an intervening number is legally immaterial.

Each page's own strict hearing classification controls transcript preprocessing,
regardless of the kind of document currently being summarized. This uses a
byte-identical vendored Focus `record_categories.py` as `focus_record_categories.py`
(SHA-256 `5c75dec26412059e88ffe20e867e33ac990bee7cf4f90eaafe5fb1b41b0dd391`),
with the canonical RecordPrep `artifacts` paths for transcript numbers, source map,
and hearing/report/motion/minute boundaries. Conflicting or non-body metadata
prevents gutter stripping, as in Focus. Verification assumes the canonical bundle
layout generated by RecordPrep, not arbitrary external manifest path overrides.

The byte-identical `focus_transcript_reading.py` vendor copy has SHA-256
`168ab3437f0edece873b27d72bf4d982c320463b172d1d101f447488186b2ec7`. Only
`search_layout`/`search_projection` are used, never display-only `render_readable`.
Confirmed prefixed, detached and flattened gutters can be removed from temporary
search text; ordinary quantities, ambiguous lists/tables and oversized pages retain
Focus's conservative fallback. Keep vendor copies and pinned tests together when
reviewing upstream changes. No runtime sibling import or Focus change is required.

## Cache, safety and freshness

The extraction runner reuses one lazy bounded page cache during a generation.
It is limited to 16 Mi normalized characters, evicts old entries, checks source stat
signatures before reuse and honors Stop between scanned pages. The source reader
rejects links/special files and bounded-read failures remain failures, not fabricated
verification results. There are no private-settings writes or source modifications.

Fingerprints include `focus-record-search-1`, the existing `focus-phrase-search-2`
and a hash of the complete source-page inventory/content plus hearing eligibility.
A change outside the current document can affect verification and therefore changes
its generation identity. Normal publication guards continue to reject changed
inputs. Historical artifacts are never relabeled as current just to reuse them.
Existing digests/finals/editions and presence-based Resume/badges remain untouched.
Explicit summary generation adopts the new method through normal freshness rules.

## Synthesis

All three narrative synthesis stages still use only quotes marked Verified. The
shared guidance explains record-wide existence and warns that the reported page,
attribution and meaning are not certified. It directs the writer to use digest
prose for context and paraphrase supported points without a suitable Verified quote.
This remains an instruction, not a new deterministic publication gate; noncompliance
is still diagnosed. Minutes retain their separate structured summary contract.

## Validation

`test_record_quote_search.py` covers preferred-page order, off-page hits, repeats,
no cross-page joining, no summary-file matches, per-page classification, conflicts,
bounded cache/reuse, source mutation, Stop, unsafe sources, unchanged reported-page
metadata, historical/new Markdown round trips, and whole-record freshness.
`test_quote_search.py` and `test_transcript_quote_search.py` retain regex/gutter
regressions. Offline SDK tests check delivery of the full synthesis guidance.
All fixtures are synthetic; any user-example check is read-only and does not update
its saved verification flag. These tests establish matching, storage and delivery
behavior, not model compliance or legal accuracy.

Final isolated combined-tree run: 1078 tests, OK with 8 skips (including separately
maintained appearance-guidance tests); resource validation, offline tool audit,
compilation and diff checks passed. The reported wrong-page example was checked
read-only: declared page 23 did not match, record-wide search did. All source pages
and saved digest Markdown bytes/mtime were unchanged. No paid calls, deployment,
user-app restart or commit was performed.
